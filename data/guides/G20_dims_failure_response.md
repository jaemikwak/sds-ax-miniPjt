# DIMS 인터페이스 실패 대응 절차

DIMS가 보내는 "[DIMS] 인터페이스 실패 알림" 메일을 받았을 때 원큐 운영 담당자가 할 일입니다.
인터페이스별 소스·타겟 테이블은 정의서(G18 정산·ERP, G19 결재·인사·영업)에서 IF ID로 찾습니다.

## 1. 확인 순서
1. 메일의 **IF ID**로 정의서에서 소스·타겟 테이블, 방향, 담당자를 확인합니다.
2. DIMS 콘솔(`https://dims.example.local`) → [실행 이력]에서 실패 건의 실행 ID와 처리 건수(성공/실패)를 확인합니다.
3. **소스 테이블**에 대상 데이터가 정상으로 들어와 있는지, **타겟 테이블**에 일부만 적재되었거나 중복이 있는지 조회합니다(운영 DB 조회는 G16의 1회성 조회 승인 필요).
4. 오류 유형별 조치를 적용합니다(아래 2).
5. 재처리 후 DIMS 실행 이력이 성공인지 확인하고, 영향 받은 업무 담당자에게 결과를 공유합니다.

## 2. 오류 유형별 조치
| 오류 | 의미 | 조치 |
|---|---|---|
| ORA-00001 (unique constraint) | 타겟 테이블에 같은 키가 이미 있음(중복 송신) | 타겟 테이블의 중복 키 데이터를 확인하고, 소스 측 중복 송신 여부를 상대 시스템 담당자에게 확인. 중복분 제외 후 재처리 |
| ORA-01400 (NULL 삽입 불가) | 소스 데이터 필수값 누락 | 소스 테이블의 해당 건을 확인해 상대 시스템에 보정 요청 |
| FILE_NOT_FOUND | 파일 수신 방식에서 파일 미도착 | 상대 시스템에 파일 생성 여부 확인, 도착 후 수동 재처리 |
| TIMEOUT / CONNECTION | DB·네트워크 연결 실패 | 방화벽·DB 상태 확인(G01, G17), 복구 후 재처리 |

## 3. 재처리
- DIMS 콘솔 → [실행 이력] → 실패 건 선택 → **[재처리]**. 운영 인터페이스 재처리는 시스템운영팀만 가능합니다.
- 같은 날 재처리 2회 이상 실패하면 상대 시스템 담당 팀과 장애 회의를 엽니다.

## 4. 기한
- 정산·전표 인터페이스(G18)는 **당일 18:00 전까지** 재처리를 완료해야 마감 일정에 영향이 없습니다.
- 메일에 재처리 기한이 적혀 있으면 그 기한을 따릅니다.
